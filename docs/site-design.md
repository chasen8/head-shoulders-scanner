# 網站設計說明（site/）

之後維護網站時照這份走。改了方向就回來改這份，不要讓程式和文件分岔。

## 主題、受眾、主要工作

- 主題：純 OHLCV 規則的頭肩底（Inverse Head and Shoulders）掃描結果，幣安 USDT 對 × 4h／1d／1w。
- 受眾：chris 本人與他分享的朋友。
- 主要工作：打開就看到「現在哪些幣、哪個週期有頭肩底、按分數排好」，點一筆就看到
  K 線上標好 LS／N1／H／N2／RS 與頸線，知道是觀察中還是已突破、距頸線多遠。
- 頁面必須寫明「型態偵測工具，不是投資建議」（頁首與頁尾各一次）。

## 設計方向：分析師的方格計算紙

頭肩底這個型態是在《Technical Analysis of Stock Trends》（Edwards & Magee, 1948）那種
**手繪在方格紙上的圖表**裡被定義出來的。網站就做成一張工程計算紙：淡綠方格底、
石墨墨色的空心／實心 K 線（印刷時代的黑白蠟燭，不用紅綠）、型態用一支鈷藍色鉛筆標註，
突破點用胭脂紅圈起來。記憶點只放一個地方：**每一筆結果前面的型態剪影**（LS→N1→H→N2→RS
的折線＋虛線頸線），清單看起來像一排標本，而不是一疊卡片。

## 色彩（`site/css/site.css` 的 `:root`）

| 名稱 | hex | 用途 |
|---|---|---|
| 方格紙 `--paper` | `#EDF2EA` | 頁面底色、上漲 K 線的空心填色 |
| 格線 `--grid` | `#C9D8CC` | 方格主線、分隔線（細格用同色 45% 透明） |
| 石墨 `--ink` | `#1F2B2A` | 文字、K 線外框與下跌實心 |
| 鉛灰 `--pencil` | `#56635F` | 次要文字（對 paper 對比 ≈5:1，可用於小字） |
| 鈷藍鉛筆 `--cobalt` | `#2F45C8` | 型態標註、頸線、選取狀態、鍵盤焦點、「觀察中」 |
| 胭脂紅 `--carmine` | `#B8174F` | 突破點、「已突破」 |

狀態語意固定：觀察中＝鈷藍外框字；已突破＝胭脂紅實心字；已過期＝鉛灰。
只有亮色版（方格紙就是識別），暫不做暗色模式。

## 字體

- `LXGW WenKai TC`（霞鶩文楷 TC，Google Fonts，400/700）：所有中文——標題、說明、標籤。
  楷書像分析師在圖邊手寫的註記，是這頁的聲音。
- `Barlow Semi Condensed`（400/500/600）：所有拉丁字母與數字（幣種代號、價格、分數），
  `font-variant-numeric: tabular-nums`。同一個 font stack 先列 Barlow 再列文楷，
  拉丁字自動走 Barlow、中文落到文楷，不需要分兩套 class。
- 字級（Bringhurst 傳統級數）：12／14／16（內文）／18／21／24／36／48（桌機標題），
  手機標題 36。內文行高 1.7（楷書筆畫細，比黑體多給一點）。行長 ≤ 40 個全形字。

## 原則

1. 前端只畫 `site/data/scan.json` 裡的值。分數、頸線端點、在頸線上方或下方
   （`neckline_side`）、下次掃描時間（`next_scan_at`）都由 `build_site.py` 算好。
   JS 只做格式化（時區、小數位、文字組句）與把 JSON 座標線性映射到 SVG。
2. 文字白話、句子式：「觀察中」「已突破」「距頸線」「高於頸線 4.8%」。專有名詞保留 LS／N1／H／N2／RS。
3. 結構即資訊：排名數字只出現在排序清單（那真的是序列）；不加裝飾性小標。
4. 動態只有一次：頁首剪影載入時像鉛筆畫出來（`prefers-reduced-motion` 時直接顯示）。
   使用者觸發的回饋（選取、篩選）即時切換，不做進場動畫。
5. 「下次掃描」只在真的有排程時才說：`next_scan_at` 只有 `--scheduled` 或 GitHub Actions
   排程觸發（`GITHUB_EVENT_NAME=schedule`）時才有值；否則是 null，頁面改說「目前沒有定時掃描，
   資料只在手動執行時更新」。（2026-10-18 repo 私有、排程停用，所以目前是 null。）
6. 品質底線：鍵盤可走完全部（清單是 button、篩選是 aria-pressed button、焦點鈷藍 2px 外框），
   空狀態告訴使用者下次掃描大約何時，載入失敗說清楚哪個檔讀不到、怎麼辦。

## 對照「AI 預設樣式」做過的修正

初版直覺是「近黑底＋綠漲紅跌蠟燭＋每筆一張圓角卡片、卡片上大分數＋漸層強調」——
正是 skill 列的第 2、4 類預設，換任何加密貨幣儀表板都長一樣。修正：

- 近黑底＋螢光綠 → 淡綠工程方格紙＋石墨墨色，題材取自型態誕生的手繪圖表。
- 綠漲紅跌 → 黑白空心／實心蠟燭；顏色只留給「型態」本身（鈷藍）與「突破」（胭脂紅），
  一眼就看到標註，不會被幾百根紅綠蠟燭淹沒。
- 圓角卡片堆疊＋陰影 → 對齊方格的清單列，以型態剪影開頭；選取列用鈷藍左邊線＋淡藍底，無陰影。
- 大數字＋小標籤的 hero → hero 就是第一名型態的標註 K 線圖本身。
- 全大寫 eyebrow、`A · B · C` 中點串接、等寬字小標、按鈕尾巴「→」：全部不用。
  meta 用完整句子（「資料更新於…，下次掃描約…」）。
- 字體不用 Inter／Noto Sans TC 這類預設黑體，改用楷書＋窄體數字。
- 避開奶油底＋陶土橘（skill 第 1 類）：底色是冷調綠，強調色是鈷藍與胭脂紅。

## 技術約定

- 無 build 工具、無 npm。`site/index.html`、`site/css/site.css`、`site/js/app.js`。
- 圖表：TradingView Lightweight Charts **5.2.1**（Apache-2.0），釘死版本：
  `https://cdn.jsdelivr.net/npm/lightweight-charts@5.2.1/dist/lightweight-charts.standalone.production.js`。
  保留圖上 TradingView logo（`attributionLogo: true`）與頁尾連結 https://www.tradingview.com/ 。
  升級版本要重新截圖檢查。
- 頸線與型態折線的 `autoscaleInfoProvider` 回傳 null：價格軸只依 K 線縮放
  （過期型態的頸線延伸很遠時不會把圖壓扁）。
- `scan.json` 格式：見 `build_site.py` 的 `build_payload` / `chart_for`
  （bars 是 `[time, open, high, low, close, volume]`，時間為 UNIX 秒 UTC）。
- 本機預覽：`build_site.py --include-stale` 產生較多筆（含已過期），在 `site/` 內
  `python -m http.server`。正式資料不帶 `--include-stale`。
- 自我檢查：無頭 Chrome 截 1440 寬與 390 寬各一張，Read 看圖批評後再改。
