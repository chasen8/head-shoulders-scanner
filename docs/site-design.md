# 網站設計說明（site/）

之後維護網站時照這份走。改了方向就回來改這份，不要讓程式和文件分岔。

## 主題、受眾、主要工作

- 主題：純 OHLCV 規則的頭肩底（Inverse Head and Shoulders）掃描結果，幣安現貨＋OKX 現貨／永續＋Gate 永續的 USDT 交易對（charter D22）× 4h／1d／1w。
- 受眾：chris 本人與他分享的朋友。
- 主要工作：打開就看到「現在哪些幣、哪個週期有頭肩底、按分數排好」，可以搜尋幣種、篩週期／狀態；
  點一筆就看到 K 線上標好 LS／N1／H／N2／RS 與頸線，知道是右肩形成中、觀察中還是已突破、距頸線多遠，
  以及 TP1／TP2／失效價（D23）。使用者把「右肩形成中」當進場區，所以這個狀態要一眼分得出來。
- 頁面必須寫明「型態偵測工具，不是投資建議」（頁首與頁尾各一次）。

## 設計方向：TradingView 淺色圖表工作台（2026-10-18 第 2 版）

使用者看過第 1 版（方格紙＋楷書）後明確要求：「不想要背景那麼雜亂」，參考圖是 TradingView
桌面版淺色圖表（白底、黑色細 K 線、右側價格軸、底部紅綠成交量）。所以這一版**不追求記憶點**，
追求安靜、專業、像看盤軟體：

- 純白背景、沒有任何紋理或漸層；分隔只用 1px 淡灰線。
- K 線圖是主角：桌機佔左側全部寬度，右側是像 TradingView 自選清單的固定欄位。
- 顏色只用在資訊上：型態五點與頸線＝強調藍，突破點＝紅色，成交量＝淡綠／淡紅。其他全部黑灰。
- 不要自行換風格（例如改回手繪、暗色、霓虹）；要改方向先問使用者。

- **K 線配色＝黑白**（定案）：上漲＝白色實體＋`#131722` 外框，下跌＝`#131722` 實心；影線 `#131722`。
  理由：照使用者參考圖；顏色留給型態與突破，不會被幾百根紅綠蠟燭淹沒。成交量用淡綠淡紅保留漲跌資訊。
- 狀態語意固定：右肩形成中＝橘字淡橘底；觀察中＝藍字淡藍底；已突破＝紅字淡紅底（與圖上紅色突破點一致）；已過期＝灰。
  Discord embed 顏色對應：形成中橘 `#F39C12`、觀察中藍 `#3498DB`、已突破紅 `#E74C3C`。
- 暫定右肩（`rs_provisional`，status `forming`）：圖上 N2→RS 改成淡藍虛線、標記文字「RS 暫定」半透明；清單剪影最後一段虛線＋
  空心橘圈；圖下一行橘字「RS 是暫定點：右肩尚未確認，會隨新 K 線變動。」；五點表 RS 標「暫定」。
- TP 線：K 線系列的 price line（整寬水平線，右側價格軸有標籤 `TP1`／`TP2`／`失效`，未突破時 TP 標籤加「預估」）。
  價格軸自動縮放會把這三條線納入（否則 TP2 常在畫面外）；頸線與型態折線仍不影響縮放。
- 只有亮色版，暫不做暗色模式。

## 字體

- `Inter`（400/500/600）＋ `Noto Sans TC`（400/500/700），Google Fonts；後備 `-apple-system`、
  `Segoe UI`、`PingFang TC`、`Microsoft JhengHei`。同一個 font stack 先 Inter 再 Noto Sans TC，
  拉丁字與數字走 Inter、中文落到 Noto Sans TC。全頁 `font-variant-numeric: tabular-nums`。
- 字級：內文 14、小字 12–13、清單幣種 14 粗、詳情標題 22（手機 20）、站名 18。
  看盤軟體的密度，不放大標題。

## 清單功能（結果可能上百筆）

- 搜尋：幣種代號包含字串（不分大小寫、忽略空白）。
- 篩選：週期、狀態（aria-pressed 按鈕）；每顆按鈕的數字是「套用其他篩選後」的筆數。
- 排序：分數高到低（`rank`）、形狀分高到低（`shape_score`，D26）、離頸線最近（`distance_to_neckline`）、最新訊號（`signal_time`）、幣種名稱。
  只用 JSON 欄位排序，不重算。
- 一次渲染 150 筆，「再顯示 N 個」載入下一批；網址 hash 指到的那筆一定顯示。
- 每列：型態剪影（`shape` 的五點折線＋藍虛線頸線＋紅色突破點）、幣種、週期、交易所／市場標籤（例：OKX 永續）、
  狀態標籤、距頸線、形狀分（`形狀 44`）、分數。
- 詳細頁「形狀驗證」區（D26，橫跨三欄、放在分數拆解之前）：每條 V1、V2、V2r（R² 參考）、V3a、V3b、V3c、V4 一列，
  欄位＝項目＋短名、一句白話「檢查什麼」、數值、門檻、結果（通過／未通過／不適用／參考）。值、門檻與通過與否全來自
  scan.json 每筆的 `shape_checks`（build_site.py 用 `validation.shape_checks` 算好），前端只格式化；標題列另有「形狀分」。
  stale 的摘要依 `stale_reason` 說明（已漲過頭／突破失敗／過期）。
- 狀態篩選順序：全部、右肩形成中、觀察中、已突破（已過期只在資料有時出現）。

## 資料與原則

1. 前端只畫 build_site.py 產出的值。分數、頸線端點、`neckline_side`、`next_scan_at` 都由 Python 算好；
   JS 只做格式化（時區、小數位、文字組句）、篩選排序與把 JSON 座標線性映射到 SVG。
2. **拆檔**：`site/data/scan.json` 只有 metadata＋每筆摘要（OUTPUT_FIELDS＋`rank`、`neckline_side`、`shape_checks`、
   `chart_file`、`shape`、`rs_provisional`）；畫圖資料在 `site/data/bars/<檔名>.json`（`bars`、`points`、`neckline`、
   `breakout`、`levels`＝[{key,label,price}] 的 TP1/TP2/失效價、`levels_estimated`、`rs_provisional`；RS 點暫定時帶
   `"provisional": true`），點選該筆時才 fetch，並在頁面內快取。TP 數值是偵測器輸出的 `tp1`／`tp2`／`invalidation_price`，
   前端不重算（D17）。讀不到時圖表區顯示檔名與「再試一次」，其他數據照常顯示。
3. 文字白話、句子式：「右肩形成中」「觀察中」「已突破」「高於頸線 4.8%」。專有名詞保留 LS／N1／H／N2／RS、TP1／TP2。
   詳細頁「目標與失效」區列 TP1、TP2、失效價與突破價（未突破時寫「預估突破價（目前頸線）」並說明 TP 是預估）；
   「量測」區列左右肩跌幅、頭到頸線漲幅。標題列有「在 TradingView 開啟」，連結用 `tv_symbol`。
   價格位數依數量級：≥1000 兩位、≥1 三位、≥0.01 四位，更小的保留約 4 位有效數字（0.0001750），
   與 `notify_discord.py` 同一規則。
4. 沒有進場動畫；選取、篩選即時切換。手機捲到圖表時 `prefers-reduced-motion` 改成瞬間跳。
5. 「下次掃描」只在真的有排程時才說（`next_scan_at` 只有 `--scheduled` 或 `GITHUB_EVENT_NAME=schedule`
   才有值；否則頁面說「目前沒有定時掃描」）。頁首 meta 會寫掃描了幾個幣種、幾組 K 線抓取失敗。
6. 品質底線：鍵盤可走完全部（清單是 button、↑↓ 移動；篩選是 aria-pressed button；搜尋與排序有 label；
   焦點 2px 藍外框），對比 ≥ 4.5:1 的文字色，空狀態／篩選無結果／scan.json 讀不到／單筆 K 線檔讀不到／
   圖表程式庫載入失敗都有說明。

## 技術約定

- 無 build 工具、無 npm。`site/index.html`、`site/css/site.css`、`site/js/app.js`。
- 圖表：TradingView Lightweight Charts **5.2.1**（Apache-2.0），釘死版本：
  `https://cdn.jsdelivr.net/npm/lightweight-charts@5.2.1/dist/lightweight-charts.standalone.production.js`。
  保留圖上 TradingView logo（`attributionLogo: true`）與頁尾連結 https://www.tradingview.com/ 。
  升級版本要重新截圖檢查。
- 頸線與型態折線的 `autoscaleInfoProvider` 回傳 null：價格軸只依 K 線縮放。
- 格式：見 `build_site.py` 的 `build_payload` / `chart_for` / `shape_for`
  （bars 是 `[time, open, high, low, close, volume]`，時間為 UNIX 秒 UTC；`shape` 是 `[time, price]` 對）。
- 本機預覽：`build_site.py --include-stale` 產生較多筆（含已過期），在 `site/` 內
  `python -m http.server`。正式資料不帶 `--include-stale`。
- 自我檢查：無頭 Chrome 截 1440 寬與 390 寬（iframe 包）各一張，Read 看圖批評後再改。
